THE THREE FIXES (locked scope)
Fix #1 — Wrap three storage calls in try/catch
The form currently has three places where localStorage or sessionStorage is accessed without try/catch protection. These calls throw SecurityError in iPhone Safari cross-origin iframe contexts, which causes the form to crash on initial render.
Location 1: client/src/components/SimpleQuoteForm.jsx line 29
Current:
vehicleType: localStorage.getItem('selectedVehicleType') || "",
Change to:
vehicleType: (() => { try { return localStorage.getItem('selectedVehicleType') || ""; } catch (_) { return ""; } })(),
Location 2: client/src/components/SimpleQuoteForm.jsx around line 194-197
Current:
if (value) {
  localStorage.setItem('selectedVehicleType', value);
}
Change to:
if (value) {
  try { localStorage.setItem('selectedVehicleType', value); } catch (_) {}
}
Location 3: client/src/components/SimpleQuoteForm.jsx around line 173-174
Current:
sessionStorage.setItem('parent_attribution_data', JSON.stringify(parentParams));
Change to:
try { sessionStorage.setItem('parent_attribution_data', JSON.stringify(parentParams)); } catch (_) {}
What this fix does NOT do:

Does not change any function name, variable name, or component structure
Does not change what value is stored
Does not change what value is read
Does not change when storage is accessed
Does not affect any browser other than Safari (in non-Safari browsers, the try blocks succeed and behavior is identical to today)

Fix #2 — Replace the alert() submission error with an inline error message
The form currently shows submission errors via alert(), which is silently suppressed in iPhone Safari cross-origin iframes.
Location: client/src/components/SimpleQuoteForm.jsx around line 629
Current:
alert("There was an error processing your request. Please try again.");
Change to:
setValidationErrors([{ field: 'submit', message: 'There was an error processing your request. Please try again.' }]);
This reuses the existing validationErrors state and the existing <div className="validation-errors"> display block. The error renders in the same place validation errors already render. No new state variables, no new components, no new CSS.
Verification required before approval:

Confirm that setValidationErrors is in scope at this line
Confirm that the existing error display block correctly renders errors with field: 'submit'
Confirm that the error block's CSS does not depend on specific field values
Confirm that no other code path expects an alert() to fire here (e.g., a downstream test or a behavior dependency)

What this fix does NOT do:

Does not change any other error handling in the form
Does not change the alert behavior anywhere else in the codebase
Does not modify the validation error display CSS or component structure
Does not change when errors are shown

Fix #3 — Add autocomplete attributes to name, phone, email
The form's contact fields lack autocomplete attributes, which suppresses iOS Safari autofill suggestions inside cross-origin iframes.
Location: client/src/components/SimpleQuoteForm.jsx around lines 814-844
For the three contact field inputs (name, phone, email), add one attribute to each:

Name input: add autocomplete="name"
Phone input: add autocomplete="tel"
Email input: add autocomplete="email"

Each is one new attribute on an existing element. No other attribute changes. No element structure changes. No styling changes.
What this fix does NOT do:

Does not change the placeholder text
Does not change the input types
Does not change validation
Does not change the name HTML attribute (which browsers use for form submission, separate from autocomplete)
Does not affect autofill on the location, vehicle, or date fields
